# Migracja AO3401A — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zastąpić IRLZ44N tranzystorem AO3401A (P-MOS high-side + NPN), włączyć deep sleep 8 h i zweryfikować układ etapowo bez ryzyka uszkodzenia czujnika lub MT3608.

**Architecture:** Etap 0 = testy ciągłości bez ogniwa. Etap 1 = USB + `enable_deep_sleep: false` + pełne logi. Etap 2 = bateria + deep sleep 8 h + obserwacja HA. Firmware steruje GPIO4 → NPN → Gate P-MOS; HIGH = czujnik ON, bez `inverted`.

**Tech Stack:** ESPHome 2026.8, ESP32 Arduino (`toolchain: platformio`), AO3401A, 2N3904/BC547, MT3608, JSN-SR04T-V3.3.

## Global Constraints

- Sterowanie: GPIO4 **HIGH** = czujnik ON; **bez** `inverted` na `sensor_power`
- `sleep_duration: 8h` (aktywne od etapu 2)
- `pin_sensor_power: GPIO4` — bez zmian
- **Nie** łączyć OUT+ bezpośrednio na DRAIN bez SOURCE (odrzucony high-side N-MOS)
- **Nie** łączyć Q1 na IN− MT3608
- GND czujnika **prosto na GND** (nie przez MOSFET)
- R1 10k: Gate → OUT+ (pull-up); R2 10k: GPIO4 → baza NPN
- DevKit **bez** expansion board
- Ładowarka + panel — poza zakresem tego planu

## Weryfikacja końcowa etapu 1

| Kryterium | Jak sprawdzić |
|-----------|---------------|
| VCC OFF ≈ 0 V | multimetr przy GPIO4 LOW / między cyklami |
| VCC ON ≈ 5 V | multimetr podczas measure_cycle |
| Pomiar OK | log `Ultrasonic OK` |
| Brak deep sleep | brak `Beginning sleep` w logach |
| MT3608 nie gorący | dotyk po 5 min pracy |

## Ryzyka

| Ryzyko | Mitygacja |
|--------|-----------|
| Zła orientacja AO3401A | sprawdź G/S/D na adapterze |
| VCC ≈ 5 V przy OFF | brak NPN lub zły pinout |
| MT3608 gorący | zwarcie; nie Q1 na IN− |
| Brak logów | normalne po etapie 2; etap 1 = USB |
